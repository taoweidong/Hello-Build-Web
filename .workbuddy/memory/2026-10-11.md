### 实施中纠正的三处认知偏差（重要教训）
1. **URL 路径参数不是风险点**。`urls.py` 全用 `<int:vid>` / `<int:pk>`，Django path converter
   先转整数，非数字根本进不了视图函数。原报告「19 处可远程触发 500」说宽了，
   真实风险仅 **query/body 参数 9 处**。⇒ **评估 Django 项目 500 风险前，先确认路由是否用了 path converter**。
2. **`int("０")` 返回 0** —— 全角数字会通过任何 `int()` 转换。原 `parse_int` 有此漏洞，
   已加 `str.isascii()` 拦截（views + services 两处实现同步改，否则行为分叉）。
3. **`Version.pm_user_id` 有唯一约束**（一个 PM 只绑一个版本），此前无测试、无文档。
   排查时一度误判为代码 Bug，实为测试数据设计错误。已补测试锁定 + 建议加模型注释。

## 第三批优化实施（H-2 策略并发兜底）

老陶推送过 `27c653f`（纯前端样式层 biz.scss），与后端无冲突。

### Spec
`docs/superpowers/specs/2026-10-11-strategy-concurrency-guard-design.md`（先写 spec 后实施）

### 三层防御方案
1. **settings.py** SQLite `OPTIONS: {"transaction_mode": "IMMEDIATE"}` —— Django 原生支持
   （base.py:332），事务以 BEGIN IMMEDIATE 打开、进入即取写锁，串行化「校验读→写入」，
   全部写路径受益。迁移 PG/MySQL 时删除并改用 select_for_update。
2. **Strategy 模型** 条件唯一约束 `uniq_active_strategy_branch_time(branch, build_start_time, enabled=True)`
   + migration 0010。
3. **服务层** create/update 捕 IntegrityError → 40902；**views.toggle_strategy 补捕获**
   （实施中暴露的新 500 漏洞：两条同刻策略停用后先后启用，第二条启用直接炸）。

### 实测确认的关键技术事实（可复用）
- Django 5.2 SQLite 默认 `BEGIN`（DEFERRED）：`django/db/backends/sqlite3/base.py:330`，
  校验读发生在取写锁前 → check-then-act 竞态真实存在。
- SQLite `select_for_update` 是 no-op（features.py 无 has_select_for_update）——本项目不能用行锁。
- **测试库 ≠ 生产库**：Django 测试库是 shared-cache 内存库，并发写直接报
  `database table is locked`（SQLITE_LOCKED，不走 busy 等待）；生产文件库走 SQLITE_BUSY →
  busy_timeout 等待。⇒ 线程级并发断言在本项目测试基建上无法编写，靠约束测试兜底。
- **SQLite IntegrityError 消息不含约束名**！格式 `UNIQUE constraint failed: table.col1, table.col2`。
  按约束名匹配永远失败（我第一版就踩了）。按字段组合匹配：
  `"strategy.branch_id" in msg and "build_start_time" in msg`。
- **行为链澄清**：同分支同时刻冲突由 **mutex 层拦截（40902）**（check_build_mutex 同版本下
  含同分支、不排除自身候选），不是 detect_conflicts（40901 只管 smoke/analysis 阶段重叠）。
  此前我以为同分支走 40901。
