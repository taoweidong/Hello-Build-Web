# 版本策略全景(New) 页面设计（原「周视图(New)」）

日期：2026-10-11（同日两次修订：单日 → 本周 7 天；再定位为策略全景并去除抢占、优化布局）
状态：已确认

## 0. 修订记录（2026-10-11 第二次修订）

- **页面定位调整**：本页不是抢占调度页，而是「版本策略全景(New)」——展示当前选中版本的调度全景。菜单标题由「周视图(New)」改为「版本策略全景(New)」（路由 path/name 不变，`/weekly-new/index`）。
- **角色分层（对外查看 / 对内维护）**：外部人员只读查看全景；内部维护人员（admin 全部版本、pm 仅绑定版本，与后端策略写路径 `_check_pm_bound` 一致）可点击任务芯片，在编辑弹窗中修改任意调度时间与信息（分支/模板/名称/构建时间/推送模式/推送时间/启停），保存走 pm/admin 共用写路径 `PATCH /strategies/:id`（服务端统一校验），保存后周数据自动刷新。前端权限判断抽取为纯函数 `canEditPanorama`（utils/business.ts，含单测）。
- **编辑弹窗**（`views/weekly-new/components/StrategyEditDialog.vue`）：复用 `useStrategyPreview` 实时预览 + 冲突拦截（conflict 时禁止保存）；模板选项读 `/admin/templates`（admin/pm 均可读），失败降级为当前策略自身模板。弹窗 UI 单行布局：标签统一 96px 不折行、行内提示改为问号悬浮图标（label 收敛为「构建时间/推送时间」）、时间线预览两列网格且单格内超长省略。
- **去除抢占能力**：移除时段抢占体系在本页的全部痕迹——`slot-calendar` 日历拉取、`SlotChip` 抢占芯片、`BookingDialog`/`SlotDetailDialog`/`MyBookingsDrawer` 三个弹层、「已占/我的」统计与「空闲/我的/已抢占」图例。抢占相关功能仍由「时段抢占」页独立提供。
- **顺带修复的两个存量缺陷**：
  1. **预览自冲突误报**：编辑策略时预览请求未透传 id，服务端把被编辑策略自身算进互斥/阶段冲突，原时间未变即报 40902。修复：`useStrategyPreview` 编辑态透传 `id`，`POST /strategies/preview` 据此 `exclude_id`（策略配置页、系统管理策略 Tab、本页弹窗三处共用）。
  2. **PM 绑定版本 id 恒为 null**：Django 反向 OneToOne（`related_name="bound_version"`）不生成 `bound_version_id` 属性，登录载荷与策略列表的 pm 过滤全部失效。修复：User 模型显式暴露 `bound_version_id` property（含登录载荷回归测试）。
- **时段列改为精确时间点**：列标签由「08:00–09:00」区间改为单行时间点（如 06:30、12:30），时间轴覆盖 0:00~23:59 但不线性铺满——仅渲染有任务的时间点行、按时间升序、无任务时段省略；时段列收窄至 64px 单行居中避免留空；同一小时内的不同时间点（如 12:00 与 12:30）拆分为独立行；行结构按天独立，兼容每天时间点差异。
- **布局优化（减少滚动、充分利用页面）**：工具栏收敛为单行（周导航 + 版本选择 + 策略统计 + 图例）；工具栏与网格合并为单卡片；页面根节点按视口高度定高（`calc(100vh - 152px)`，过小视口回退 `min-height: 520px` 允许整页滚动），网格区 flex 撑满剩余高度，小时行 `flex: 1` 弹性分配——内容少时行高拉伸铺满视口，内容多时按 `min-height: 40px` 紧凑排列、仅网格区内部滚动。
- 移除网格标题行「…任务排布与时段抢占」与时间轴说明文案（信息量低，占用纵向空间）。

## 1. 背景与目标

在既有「周视图」（分支 × 周一~周日矩阵）之外提供独立一级菜单「版本策略全景(New)」：以**本周 7 天为列、小时段为行**构成矩阵，每个单元格展示该时段应执行的任务芯片（来自周视图同一数据源），供各角色只读纵览版本调度全景。

原「周视图」页面与「时段抢占」页面保持不动。

## 2. 关键决策（已与用户确认）

| 决策点 | 结论 |
|--------|------|
| 页面入口 | 独立一级菜单「版本策略全景(New)」（rank 13，path 仍为 `/weekly-new`） |
| 页面性质 | **调度全景**：外部人员只读查看；内部维护人员（admin / 绑定版本的 pm）可点芯片编辑任意时间与信息 |
| 矩阵形态 | **列 = 本周周一~周日 7 天**（周导航 ◀▶ + 本月周列表 + 本周按钮），**行 = 任务时间点（精确到分钟）** |
| 时间轴 | 覆盖 0:00~23:59 但不线性铺满：仅渲染有任务的时间点行，按时间升序，无任务时段省略 |
| 任务信息 | 单元格内展示落在该小时的策略任务芯片：构建（按分支配色实底）与推送（虚线描边），数据与周视图同源，策略每日循环故 7 天一致；维护人员点击芯片弹出编辑弹窗 |
| 数据来源 | 与周视图一致：`GET /api/weekly`（版本/分支/策略）；编辑走 `PATCH /strategies/:id` 共用写路径（服务端统一校验） |
| 演示数据 | seed 保证三个版本均有饱满数据：27A（3 分支 9 策略）、27B（3 分支 7 策略）、26B（3 分支 7 策略），覆盖凌晨/早/午/晚时段与普通/同步推送模式，任一版本切换均不空旷 |
| 布局 | 单卡片 + 视口定高 + 网格区内部滚动（见修订记录） |

默认假设：策略为每日循环排布（周视图后端无日期字段），故任务芯片 7 天一致；默认选中版本列表第一项（weekly 接口未选版本时不返回策略）。

## 3. 页面结构

```
┌────────────────────────────────────────────────────────────────────┐
│ [◀] 2026年10月5日 - 10月11日 [第41周▾] [▶][本周] 版本[27A▾]          │
│            策略任务 4 │ 覆盖分支 2 │ 图例: ■27A-master ■TR6 □推送    │
├────────────────────────────────────────────────────────────────────┤
│ 时段        │ 周一      周二      …                     周日        │
│ 0:00-23:59  │                                                      │
│ 06:30       │ [构建 27A-master-早间回归 06:30] × 7 天               │
│ 08:00       │ [推送 … 08:00]                                       │
│ 12:30       │ [构建 … 12:30]                                       │
│ …（行 = 有任务的时间点，非线性铺满；行高弹性拉伸铺满视口）            │
└────────────────────────────────────────────────────────────────────┘
```

- **时段列显示精确时间点**（非「08:00–09:00」区间）：时间轴覆盖 0:00~23:59，但不线性铺满 24 行——仅渲染有任务的时间点行并按时间升序，无任务时段省略；时段列窄列（64px）单行居中，避免留空。12:00 与 12:30 属不同时间点，各占一行。
- 时间点行结构按天独立（`cells` 逐日任务数组），当前策略为每日循环故 7 天一致，兼容将来每天时间点存在差异的情况。
- 任务芯片：构建 = 分支色实底白字（与周视图分支配色一致），推送 = 同色虚线描边；chip 内「阶段 · 策略名 · HH:MM」，悬停 title 显示完整信息。
- 周导航、月周下拉、版本下拉交互与修订前一致；切换周/版本重新拉取 `GET /api/weekly`。
- 空态：weekly 无数据 →「暂无数据」；所选版本无分支 →「该版本暂无分支，无法排布任务」。

## 4. 时间点归行计算（纯前端）

- 收集所选版本全部策略的 `build_start_time` 与 `push_start_time`（可空）构成时间点集合，去重后按 `HH:mm` 字典序升序（零填充格式字典序即时序）。
- 每个时间点一行，行内任务 = 起始时间与该点完全相等的构建/推送芯片；行内 7 天单元格共享同一任务数组（每日循环）。
- 无任务的时间点不产生行（省略）；行高弹性拉伸铺满视口，内容多时按最小高度 40px 仅网格区内部滚动。
